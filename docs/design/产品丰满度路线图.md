# 产品丰满度路线图（L0–L4 全部采纳 · 2026-10-29 定稿）

> 前提：课程时间不紧，**优先把东西做好**。本稿不是"功能许愿单"，而是按"一个学生从早到晚真正会用到什么"
> 来排的；每条都标了价值、形态、成本、是否动 Core、以及是否碰红线。
> **审查结论（2026-10-29）：L0–L4 全部采纳**，按 §5 分批实施；唯一不做的是"番茄暂停"。
> 与 `UI-补齐设计稿.md` 的关系：那份是 P0 缺口修复（3.25 天），本稿是 P0 之后的产品化路线。

---

## 0. 先把"做好"定清楚

四条主线，缺一条都会显得"半成品"：

1. **闭环完整**：能开始、能停、能纠错、能看结果——现在连番茄都没有启动入口。
2. **可解释**：用户知道"它为什么这么判断"，而不是一个黑箱宠物。
3. **可信**：用户能亲眼看到"到底采了什么、存在哪、怎么删"。
4. **有温度**：它是陪伴物，不是计时器；但不能用焦虑驱动（不排名、不羞辱、不诊断）。

反面清单（做多了反而坏）：排行榜、连续天数打卡、社交分享、AI 聊天、强制锁屏、摄像头/录音。

## 2. 信息架构：窗口别越加越多

现在有 4 个窗（设置/今日复盘/本周报告/宠物），再各自加会散。建议收敛为：

```
桌宠（常驻，唯一主入口）
 ├─ 菜单：开始/停止专注 · 今日复盘 · 记录 · 设置 · 隐藏 · 退出
 ├─ 欢迎窗（仅首次）
 ├─ 记录窗（Tab：本周 / 近 14 天 / 月历）   ← 合并"本周报告"与"历史"
 ├─ 今日复盘窗（保留独立：仪式感）
 └─ 设置窗（分组：提醒 / 采集与隐私 / 外观与宠物 / 高级）
```

**决策点 1**：合并「本周报告」进「记录窗」，不再单独一个窗。推荐**合并**——减少入口，周/月/历史本来就是一件事。

### L1 · 让产品站得住（可信 + 可控，约 4.75 天）

| # | 功能 | 用户价值 | UI 形态 | 成本 | Core? |
|---|---|---|---|---|---|
| L1-1 | **状态解释浮层** | 回答"你凭什么说我在游离" | 状态条旁 `?` → 小浮层：最近一次迁移原因（类别/空闲/相位）+ 最近 5 条事件（只类别与时间） | 0.5d | 否（读现有 transition/事件） |
| L1-2 | **随时手动纠错** | 不用等气泡也能说"我刚才在查资料" | 菜单/状态卡两个按钮 | 0.25d | 否（`MarkAsValid/MarkEscape` 已有） |
| L1-3 | **微重启可视化** | 逃避后知道怎么回来 | 宠物上方 2 分钟环形倒计时 + "重新开始" | 0.25d | 否（`InMicroRestart` 已有） |
| L1-4 | **番茄结束小结** | 每个 25 分钟都有即时反馈 | 复盘式小气泡/小窗：专注 X 分、切走 N 次、最长一段 | 0.5d | 否（按区间算 events） |
| L1-5 | **隐私仪表盘** | "到底采了什么"亲眼可见 | 设置页一块：今日事件 N 条、类别分布、**标题 0 条**、DB 大小、上次导出/清空；"查看最近事件（仅类别）" | 0.75d | 否 |
| L1-6 | **采集暂停粒度** | 开会/考试不想被记 | 暂停 1 小时 / 今天 / 直到手动恢复 | 0.25d | 否 |
| L1-7 | **自定义应用/关键词映射** | 解决"我的学习工具被当成娱乐" | 设置页：当前应用卡片 + 进程/标题规则列表 + 桌宠快捷设置；本地词表 | 2.0–2.5d | **是**（`AppClassifier`/`rules.json` + 测试） |
| L1-8 | **单实例** | 双击两次不会两只宠物、两个托盘、抢数据库 | 互斥量；再启动时唤醒已有实例 | 0.25d | 否 |
| L1-9 | **全局异常兜底** | 崩溃不再静默消失 | `DispatcherUnhandledException` + `AppDomain` 记日志 + 友好提示 | 0.25d | 否 |
| L1-10 | **高 DPI 适配** | 现在没有 manifest，多屏/缩放下宠物会糊 | `PerMonitorV2` manifest，宠物按 DPI 缩放 | 0.25d | 否 |
| L1-11 | **低动态模式** | 关掉常驻动画：省 CPU、也更适合容易分心的人 | 设置开关：呼吸/摇摆/眨眼可关；顺带解老机 9.47% | 0.5d | 否 |

> L1-7 是最值钱的一条：分类不准，后面所有状态和复盘都跟着错。它动 Core，必须配单测（现有映射表测试可扩展）。
> **扩展版（2026-10-29 已实施）**：用户规则 + 浏览器标题清洗 + 站点词表 + 分类原因 + Uncertain 角标 +
> 日志去标题；4 个 commit，测试 134/134。完整设计见 [分类与白名单设计稿](分类与白名单设计稿.md)。

## 4. 确认范围（全部采纳）

**L0–L4 全做**，约 **15–16 天**（含联调余量）。不设"v1.1 砍项"；唯一不做的是"番茄暂停"。

理由：
- L0 让产品"能用"；
- L1 让产品"可信、可解释、不出洋相"（单实例/DPI/异常兜底是质量底线）；
- L2 让产品"有东西可看"，课程展示拿得出手；
- L3/L4 决定它像"产品"还是"作业"。

**明确不做**：排行榜、连续打卡、社交分享、AI 聊天、强制锁屏、屏幕/摄像头/麦克风、任何云端、番茄暂停。

## 6. 红线自检（每条新功能都要过）

- 状态解释只显示**类别枚举、空闲秒数、番茄相位**，不显示窗口标题原文；
- 自定义映射只存用户输入的进程名/关键词，不上传、不读路径；
- 隐私仪表盘只统计行数与类别，不展示标题；
- "明天第一件事"是用户自己写的，存本地 settings，不参与状态判断；
- 图片卡只导出聚合数字，不含任何事件明细；
- 所有提醒仍可关、有时段、有上限；不排名、不做连续天数施压；
- 不新增任何摄像头/录音/屏幕 API。

## 7. 已确认（2026-10-29）

1. 记录窗**合并**周报（周 / 14 天 / 月历三个 Tab）。
2. 自定义应用映射**做**（动 Core，配单测）。
3. 番茄暂停**不做**。
4. 深色模式**照做**（排在 L3，不提前）。
5. 图片卡**做**（本轮 L2-5）。
6. 单实例 / DPI / 异常兜底**算 v1.0**，优先级最高（批次 4）。

## 8. 与 SRS 的关系

- L0-1/2/3/4/5/6 是 V0.3 已承诺、实现缺失的补齐，不改需求；
- L1-7（自定义映射）是**新增功能**，需要进 SRS（建议 V0.4 增补一条 FR-11，含隐私约束）；
- L1-5（隐私仪表盘）可作为 FR-07 的验收增强，不新增编号；
- 其余（月历/黄金时段/夜间/声音/深色/自启）属于体验增强，建议放在本路线图，不急着扩 SRS 基线。
