# 分类与白名单设计稿（L1-7 扩展 · 2026-10-29）

> 状态：**已审查通过并实施（2026-10-29）**。6 条决策按推荐落地；实施记录见 §10，测试 134/134。
> 范围：用户分类规则、浏览器站点识别、分类可解释、Uncertain 可见、日志去标题。
> 不做：读 URL、浏览器扩展、域名级识别、新增 Shopping/Forum 枚举、状态机判定改动。
> 关联：`产品丰满度路线图.md` L1-7、L1-1；`UI-补齐设计稿.md`；SRS V0.4 FR-02/FR-11。

## 0. 一句话

把 `AppCatalog.Classify` 从「四张硬编码表 + 浏览器标题关键词」升级为
**「用户规则 > 内置进程表 > 内置站点词表 > 宿主默认 > Unknown」的纯函数解析器**；
分类结果带**来源、命中规则与原因**；`Uncertain` 在宠物上有一个 `?` 角标；
常规日志不再写窗口标题。**不读 URL、不装扩展、不猜。**

## 1. 问题复现与根因

用户反馈「DSH 被当成娱乐」——实际链路是：

```
DeepSeek Harness（不在任何内置表、也不是浏览器宿主）
  → AppCatalog.Classify = Unknown
  → FocusStateMachine R7 = Uncertain
  → PetViewModel.OnFocusTransition(Uncertain) 不改变姿态
  → 上一个窗口（QQ：Social → Distracted → 蔫）的姿态被继承
```

两个缺陷：

1. **分类表没有 DSH，也没有用户白名单**：`Classify` 是静态函数，没有接收用户规则的入口，
   用户无法表达「这是我的学习/工作工具」；
2. **Uncertain 在 UI 上没有可见表达**：姿态继承让「不确定」看起来像「它判我娱乐」。

顺带的隐私表述不一致：`MonitoringLoop` 的 Debug 日志会写窗口标题，
而 SRS FR-02 写的是「窗口信息仅在内存中用于本地分类，不落库」。日志不是数据库，但确实落盘。

## 2. 已确认的 6 条决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 网页识别只做标题级，不读 URL、不做浏览器扩展 | 确认 |
| 2 | 标题规则默认只对浏览器生效，高级可勾「对所有窗口」 | 确认 |
| 3 | 「不打扰」作为独立目标，映射 `Unknown` | 确认 |
| 4 | 纠正后只**建议**加规则，不自动改判定 | 确认 |
| 5 | 常规日志移除窗口标题，仅显式诊断开关下记录 | 确认 |
| 6 | 冲突按用户规则列表顺序先命中 | 确认（进程规则整体先于标题规则，见 §4.3） |

## 3. 设计原则与红线

- **输入不变**：仍然只有前台进程名 + 窗口标题文本 + 空闲时长；不读 URL、页面内容、屏幕、键盘。
- **不猜**：标题没有站名/关键词就保持 `Unknown`，由用户补规则；宁可「不确定」也不误判。
- **用户优先**：用户规则永远高于内置表；内置表只做开箱默认值。
- **可解释**：每个分类结果都能回答「凭什么」；UI 显示来源与原因，日志只记结构化字段。
- **本地优先**：规则只存 `%LOCALAPPDATA%\Yaya\rules.json`；可导出、可恢复默认，不上传。
- **低打扰**：Uncertain 只加标识不弹窗；纠错建议可忽略、每进程每会话最多一次。

## 4. 领域模型（Core）

### 4.1 规则

```csharp
public enum RuleTarget { Process, Title }
public enum RuleMatch { Exact, Contains }
public enum RuleCategory { Study, Utility, Entertainment, Social, Ignore }

public sealed record CategoryRule(
    string Id,              // Guid N，日志只记这个
    RuleTarget Target,
    RuleMatch Match,
    string Value,           // 用户输入；trim 后 1–128 字符
    RuleCategory Category,
    bool BrowserOnly,       // 仅 Title 有意义；默认 true
    bool Enabled);
```

约定：

- `Process` + `Exact`：进程名大小写不敏感、trim 后全等（DSH 用这条）；
- `Process` + `Contains`：进程名包含子串（Electron/UWP 变体兜底）；
- `Title` + `Contains`：标题包含子串，大小写不敏感；`Title` + `Exact` 保留但 UI 默认不推荐；
- `BrowserOnly=true` 时只对浏览器宿主进程生效；`false` 时对所有窗口生效；
- `Ignore` 映射为 `AppCategory.Unknown`，并带 `IsMuted=true`；
- `Id` 只用于日志/导出关联，不参与匹配；
- 空值、超长、未定义枚举在加载时丢弃并记 Warning；丢弃不阻塞启动。

### 4.2 分类结果

```csharp
public enum ClassificationSource
{
    Unknown,          // 未识别
    UserProcess,      // 用户进程规则
    UserTitle,        // 用户标题规则
    BuiltinProcess,   // 内置进程表
    BuiltinSite,      // 内置站点词表
    BrowserFallback,  // 浏览器宿主但标题未命中
}

public sealed record ClassificationResult(
    AppCategory Category,
    ClassificationSource Source,
    string? RuleId,        // 用户规则命中时
    string? MatchedSite,   // 内置站点词命中时（站名，不是整条标题）
    bool IsMuted,          // Ignore 规则
    string Reason);        // 面向用户的一句话；不含完整标题
```

`Reason` 示例（只用于 UI/“为什么”面板，不进日志）：

- 用户进程规则：`命中你的规则：进程名 = DeepSeek Harness → 工具`
- 内置进程：`内置映射：Code → 学习`
- 站点：`浏览器标题命中站点「GitHub」→ 学习`
- 浏览器兜底：`浏览器标题未命中任何站点词 → 未知（不猜）`
- 未知：`进程名不在内置表，也不是浏览器 → 不判断、不提醒`
- Ignore：`你把它设为「不打扰」→ 不计入学习，也不提醒`

### 4.3 解析顺序（先命中先返回）

1. **用户进程规则**（Enabled，同组内按列表顺序，Exact/Contains 混排）；
2. **用户标题规则**（Enabled，同组内按列表顺序）：`BrowserOnly && !浏览器` 跳过；
3. **内置进程表**（Study / Entertainment / Social / Utility）；
4. **内置站点词表**（仅浏览器宿主，标题清洗后按词长降序匹配）；
5. **浏览器兜底** → `Unknown`；
6. **未知进程** → `Unknown`。

> 为什么进程规则整体先于标题规则：进程名是强信号，标题是启发式；同组内再按列表顺序。
> 这同时满足「用户规则 > 内置」和「冲突按列表顺序」两条。

浏览器判定使用 `AppCatalog.IsBrowserHost(processName)`；非浏览器窗口的标题规则
（`BrowserOnly=false`）直接匹配原始标题（截断后），不做浏览器后缀清洗。

### 4.4 匹配与规范化

- 进程名 / 标题：`Trim()`，内部连续空白折叠为一个空格；匹配用 `OrdinalIgnoreCase`；
- 标题先截断到 **512 字符**（防异常长标题），再做清洗与匹配；
- 中文按原文匹配，不做繁简转换；
- 站点词表匹配：`cleanedTitle.Contains(keyword, OrdinalIgnoreCase)`；
- 站点词按**词长降序**匹配（长词优先），同长按词表顺序：
  「微信读书」先于「微信」、「QQ音乐」先于「QQ」、「中国大学MOOC」先于「MOOC」；
- 不引入正则做用户规则；只有浏览器标题清洗用预编译正则。

### 4.5 Ignore（不打扰）语义

- `RuleCategory.Ignore` → `AppCategory.Unknown` + `IsMuted=true`；
- 状态机 R7 → `Uncertain`，不询问、不改变姿态；
- 该窗口**不计入有效专注**，也不产生游离/轻问；
- UI 标注「不打扰（不计入专注）」，避免用户误以为仍在统计。

### 5.4 与现状的差异（行为变更）

- **移除**旧的三组通用标题关键词（除站名外，还包括 `课程/教程/网课/学习/文档/论文/PDF`
  与 `游戏/视频` 等）：没有站名就不猜，避免「标题里有‘文档’就判学习」；
- 站名（哔哩哔哩、知网、微信等）统一迁移到站点词表，仍能命中；
- 旧测试 `msedge + "高等数学 网课 - 课程中心"` 会从 Study 变成 Unknown；
  改为用「中国大学MOOC / 学习通 / 知网」等站名断言；
- 这是有意的产品取舍：**宁可 Unknown + 问用户，也不误判**。需要通用词的场景由用户标题规则补。

## 6. App 层结构

### 6.1 rules.json

路径：`%LOCALAPPDATA%\Yaya\rules.json`（与 settings.json 同目录）。

```json
{
  "version": 1,
  "rules": [
    {
      "id": "a1b2c3d4e5f60718",
      "target": "Process",
      "match": "Exact",
      "value": "DeepSeek Harness",
      "category": "Utility",
      "browserOnly": false,
      "enabled": true
    },
    {
      "id": "0f1e2d3c4b5a6978",
      "target": "Title",
      "match": "Contains",
      "value": "知网",
      "category": "Study",
      "browserOnly": true,
      "enabled": true
    }
  ]
}
```

- **数组顺序即优先级**（不额外存 `order` 字段，避免双事实源）；
- 枚举用字符串（`JsonStringEnumConverter`），便于手改；
- 保存用「临时文件 + 替换」原子写；损坏文件重命名为 `rules.corrupt-<时间戳>.json`
  后按空规则启动并记 Warning，绝不阻塞启动；
- `version > 1` 的文件只读不覆盖，提示用户升级；v1 产品先按 1 处理；
- 只存用户输入的字符串，不存标题、进程路径、URL。

### 6.2 RuleManager（App 服务）

```
RuleManager
  ├─ Load(dataDir) / Save()
  ├─ IReadOnlyList<CategoryRule> Current
  ├─ AddProcessRule(processName, category)     // 桌宠/当前应用一键
  ├─ AddTitleRule(value, category, browserOnly)
  ├─ Replace(orderedRules)                      // 设置页规则列表
  ├─ ResetToDefault()                           // 清空用户规则（内置不动）
  └─ event Changed
```

- `Changed` → 保存 → `MonitoringLoop.UpdateClassifier(new AppClassifier(rules))` → 刷新设置页/浮层；
- 重复规则（同 Target/Match/Value，大小写不敏感）更新类别而不是新增，避免列表膨胀；
- 加规则默认插到所属组顶部（新规则优先），用户可再上下移。

### 6.3 MonitoringLoop 暴露

新增（不改 Core 状态机）：

```csharp
public ClassificationResult LastClassification { get; private set; }
public string LastProcessName { get; private set; }   // UI 展示；日志按 §8.1 分级
public bool LastIsBrowserHost { get; private set; }
public FocusState CurrentState => _machine.Current;

public event EventHandler<ClassificationResult>? ClassificationChanged;
public event EventHandler<FocusState>? StateEvaluated;   // 每轮都发，供 Uncertain 角标
```

- 每轮 `Evaluate` 后都发 `StateEvaluated`（即使状态没迁移）——否则初始就是 Uncertain 时
  角标永远不出现；
- `ClassificationChanged` 只在进程名/来源/类别/规则变化时发（每 2 秒最多一次）；
- `UpdateClassifier(AppClassifier)` 由 RuleManager 调用，UI 线程内替换引用，无锁。

### 6.4 导出与清空

- `DataExporter.BuildJson` 增加 `rules`（用户输入的规则）与 `rulesVersion`；
- 不导出标题、进程路径、URL；`api_key` 仍剔除；
- 一键清空保留 `settings.json` 与 `rules.json`（用户偏好，非采集数据）；
- 设置页规则区提供「恢复默认」（清空全部用户规则，二次确认），内置表不受影响。

## 7. UI 设计

### 7.1 设置页 ·「应用与网页」（单窗内联）

设置页仍是单窗（不新增规则窗口）：宽度 400px 不变，高度维持 600，
规则区放在现有 ScrollViewer 内滚动（不为新内容再加高窗口）：

```
┌ 应用与网页 ─────────────────────────────┐
│ 当前前台：DeepSeek Harness               │
│ 类别：工具（你的规则）                    │
│ 依据：进程名 = DeepSeek Harness → 工具    │
│ [改为 学习] [工具] [娱乐] [社交] [不打扰] │
│ ── 规则（先命中先返回）──                 │
│ [✓] 进程·精确 "DeepSeek Harness"   ↑ ↓ × │
│     类别[工具▼]  仅浏览器☐               │
│ [✓] 标题·包含 "知网"               ↑ ↓ × │
│     类别[学习▼]  仅浏览器☑               │
│ 添加：[进程▼][精确▼][值______][类别▼][+] │
│ 规则 2 条                    [恢复默认]   │
│ 只在本机生效；只保存你输入的字符串；      │
│ 不读取 URL / 网页内容。                   │
└─────────────────────────────────────────┘
```

- 当前前台为空 → 「未识别到前台应用」，按钮禁用；
- 浏览器窗口 → 五个快捷按钮改为「浏览器请用标题规则…」，在下方添加表单预填站点词
  （如果当前命中了站点词）或空白标题规则；
- 采集暂停时显示「采集已暂停，下面是最后一次识别结果」；
- 块底说明是隐私红线文案，必须有；
- 规则值 trim 后 1–128 字符；空值/重复给出即时提示，不写入；
- 「标题」的「仅浏览器」默认勾选；勾掉即「所有窗口」；
- 上下移只在同组内；进程规则整体永远先于标题规则（UI 用分组表达）；
- 恢复默认二次确认：「清空全部自定义规则？内置表不受影响。」

> 为什么内联而不是新开规则窗：路线图 §2「窗口别越加越多」；规则的日常操作是
> 「看一眼当前应用、改一条、加一条」，留在设置页最短路径。400px 下用两行式规则行
> （第一行：启用/目标/值/排序；第二行：类别/仅浏览器）即可放下。

### 7.2 Uncertain 角标与「为什么」浮层（宠物窗内 Popup，不新开窗）

**角标**：宠物区右上角 18×18 圆形 `?`，琥珀色，`ToolTip="不确定，点我看原因"`：

- 仅在 `FocusState == Uncertain` 时显示；不改姿态、不弹窗、不挡宠物；
- 点击打开浮层；鼠标穿透开启时不可点（设置页已解释）；
- `StateEvaluated` 每轮驱动，初始就是 Uncertain 也会显示。

`?` 角标点击后在宠物窗上方弹出一个 `Popup`（WPF 原生，非独立 Window，不占任务栏）：

```
┌ 芽芽现在看到 ─────────────────┐
│ 前台：DeepSeek Harness         │
│ 类别：未知（未识别）            │
│ 判定：不确定 — 不打扰           │
│ 原因：进程名不在内置表，也不是  │
│      浏览器 → 不判断、不提醒。  │
│ [学习][工具][娱乐][社交][不打扰]│
│ [打开设置…]              [关闭] │
└───────────────────────────────┘
```

- 浮层 300×240，`StaysOpen=false`（点外面关闭），定位在角标上方/旁边；
- 五类按钮直接 `RuleManager.AddProcessRule`（非浏览器）；浏览器显示「浏览器请用标题规则」
  并只保留「打开设置…」；
- 显示的「前台」是进程名；浏览器显示「浏览器窗口」+ 命中的站点词，不显示整条标题；
- 面板打开期间随 `ClassificationChanged` / `StateEvaluated` 刷新；
- 判定行只显示 专注/游离/不确定 与是否打扰，不展开状态机内部原因（完整迁移原因留给 L1-1）。

### 7.3 桌宠菜单 ·「把当前应用设为…」

```

──────────────
把当前应用设为…  ▸ 学习
                  工具
                  娱乐
                  社交
                  不打扰
今日复盘…
本周报告…
历史记录…
设置…
隐藏宠物
──────────────
退出
```

- 非浏览器：一键建 `Process/Exact` 规则（值 = 当前进程名），托盘气泡确认
  「已设为工具：DeepSeek Harness」；
- 浏览器：不建进程规则（会把所有网页都设成同一类），改为打开设置页并在添加表单
  预填站点词/空白标题规则；
- 当前无前台进程：托盘气泡「还没识别到前台应用」；
- 建规则后立刻 `RuleManager.Changed` → 分类器热更新，下一轮 2 秒内生效。

### 7.4 纠正后建议（只建议，不自动）

用户点「有效查资料」且当时类别是 `Entertainment`/`Social`、非浏览器、该进程还没有用户规则时，
气泡关闭后追加一条**建议气泡**：

```
刚才那个是 QQ。
以后把 QQ 算作学习？
[设为学习]  [不用]
```

- 10 秒无操作自动消失；每进程每会话最多建议一次，点「不用」本会话不再提；
- 点「设为学习」→ `RuleManager.AddProcessRule(process, Study)`，下一轮生效；
- **绝不自动加规则**；建议文案不含标题，只含进程名；
- 如果此时有新轻问，建议气泡让位（关闭建议）。

## 8. 隐私与日志

### 8.1 日志分级

| 级别 | 内容 | 默认 |
|---|---|---|
| Info（状态迁移） | 类别、来源、规则 Id、空闲毫秒、From→To | 开 |
| Debug（分类上下文） | 进程名、来源、规则 Id | 开（Debug 级） |
| Diagnostic（诊断） | 窗口标题全文 | **关**，需设置里显式开启 |

- 删除现有 `Log.Debug("迁移上下文：进程 {ProcessName}，标题“{Title}”")`；
- 规则**值**不进日志，只记 `RuleId`；站点词也不进日志（只记来源=BuiltinSite）；
- 新增 `AppSettings.DiagnosticLogging`（默认 false），设置页底部「高级」：
  「诊断日志（会记录窗口标题，仅排障用；默认关闭）」；
- 开启后写 `Log.Debug("诊断上下文：标题长度 {Length}，标题 {Title}")`；
- 标题永远不落库、不导出、不进提醒气泡。

### 8.2 导出与清空

- JSON 导出增加 `rules`（用户规则值）与 `rulesVersion`；不含标题；
- `api_key` 仍剔除；
- 一键清空保留 `settings.json` / `rules.json`；设置页规则区「恢复默认」清空用户规则。

## 11. 风险与取舍

| 风险 | 处置 |
|---|---|
| 浏览器标题格式碎片化 | 只清洗已知宿主后缀；未识别宿主 → Unknown；用户可加「所有窗口」标题规则 |
| 站点词误判（如「微博」出现在新闻标题） | 词表只认站名；用户可加更具体规则/忽略；不猜全文语义 |
| B 站网课 vs 看番无法区分 | 首版单关键词 OR；后续可加「AND 规则」（两关键词同时命中），不上正则 |
| UWP `ApplicationFrameHost` / Electron 变体 | 进程 Contains + 标题规则兜底；仍 Unknown 时靠用户规则 |
| 规则顺序复杂 | UI 分「进程/标题」两组，组内上下移；组间优先级写死并说明 |
| 建议气泡打扰 | 每进程每会话一次、10 秒自动消失、可「不用」；不自动改判定 |
| 诊断日志泄露标题 | 默认关闭、设置页明确警告、仅本地；一键清空可删日志 |
| 旧测试/行为变更 | 明确移除通用词兜底，更新测试与 SRS 说明；在变更记录里写清 |
