# 发布演练记录（2026-10）

目的：验证 Yaya.App 能打出可分发、在干净 Windows 机器上运行的单文件 exe。
结论汇总见文末"演练结论"。

## 一、发布配置

- 配置文件：`src/Yaya.App/Properties/PublishProfiles/win-x64.pubxml`
  （Release / win-x64 / 自包含 / 单文件 / `EnableCompressionInSingleFile` / 不产符号）。
  注意：仓库 `.gitignore` 第 193 行 `*.pubxml` 默认忽略发布配置（防 Web 发布凭据入库），
  本配置仅含本地文件夹发布参数，已 `git add -f` 单文件入库。
- 发布命令：`dotnet publish src/Yaya.App -p:PublishProfile=win-x64`（首次约 47 秒，之后增量）。
- 产物：`Yaya.App.exe` 约 **74.9MB**（内嵌 6 张宠物图后）；目录附带 `Yaya.Core.pdb` 可忽略。
- `DEBUG_HOTKEYS` 在 Release 下不参与编译（`DEBUG` 与 `DEBUG_HOTKEYS` 均未定义）。

## 二、资源打包问题与修复（方案 A：三级回退）

**问题（已实证）**：.NET 单文件发布默认不打包 `Content`，6 张宠物图以松散目录躺在 exe 旁；
只拷 exe 到干净目录运行时日志为 `真图 0/6，占位 6`（不崩溃，但显示矢量占位）。

**修复**：同一批 PNG 同时标记 `EmbeddedResource`；`PetAssets` 改为三级回退——
**磁盘（exe 旁 `Assets/pet/`）> 内嵌资源 > 矢量占位**。磁盘优先保留"放图覆盖"自由度。

**复测结论**：

| 场景 | 日志（宠物图加载完成） |
| --- | --- |
| 裸 exe（发布形态） | `真图 6/6（磁盘 0 / 内嵌 6），占位 0` |
| exe 旁放 `Assets/pet/pet_healthy.png` | `真图 6/6（磁盘 1 / 内嵌 5），占位 0`（磁盘优先实证） |

## 四、本机冒烟（干净目录、非 dotnet 启动）

- 数据落点 ✅：`%LOCALAPPDATA%\Yaya\`（yaya.db / logs / settings.json），exe 目录无写入。
- 完整链路 ✅（含人工交互）：启动 → 托盘图标 → 宠物窗真图 → 当日复盘自动生成并弹窗 →
  「明天开始」以 12 分钟单次覆盖启动番茄（未写用户默认设置）→ 状态迁移与事件落库 →
  托盘退出（优雅）→ 日志「退出事件行已写入」。
- 教训：演练目录不要放在 `%TEMP%`（本次有 exe 在临时目录过夜后被系统清理，Defender 无拦截记录）；
  正式验证目录 `D:\yaya-drill`。

## 五、资源红线复测（30 分钟挂机）

| 指标 | 实测 | 红线 | 结论 |

| 内存（工作集） | 197.8–205.7 MB，均值约 202 MB | ≤ 300MB | ✅ 通过（单文件宿主内存映射约占 100MB，私有内存仅 ~99MB） |

**CPU 超标归因（对照实验）**：停用宠物窗常驻动画（呼吸 + 摇摆）后重测 6 分钟，
稳态 CPU 降至 **0.03–0.44%**（采样：`D:\yaya-drill\soak6.csv`）。
根因：WPF 透明分层窗口上的无限循环 Storyboard 每帧重绘视觉树。
**候选对策（待产品决策，本轮不改代码）**：对动画层加 `CacheMode="BitmapCache"`
（把子树缓存为位图，变换动画退化为廉价位图变换），预期回到 1–2% 以内，
内存代价约 200×360 位图 ≈ 可忽略。诊断期间对 `PetWindow.OnLoaded` 的临时改动已还原。

采样原始数据：`D:\yaya-drill\soak.csv`（路演验收证据，建议另附任务管理器截图）。
